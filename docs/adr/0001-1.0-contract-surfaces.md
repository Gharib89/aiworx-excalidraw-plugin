# ADR-0001 — The 1.0 contract surfaces survive the breaking-change review unrenamed

- **Status**: accepted
- **Date**: 2026-08-08
- **Context**: issue #93, under the 0.5.0 polish wave (#90)

## Context

1.0 freezes three surfaces: the **skill workflow**, the **CLI flags**, and the
**gate's problem codes**. After 1.0 each rename costs a major version, so this is
the last cheap chance to change a name or a shape we would regret. This ADR is the
record of that pass: every flag, every problem code and every workflow step was
reviewed, and each carries a disposition below.

Evidence was the source plus real session transcripts on the maintainer's machine
(roughly six excalidraw working sessions, July–August 2026), read for what agents
actually retry on rather than for what reads badly. The transcripts showed **no
retry episodes and no flag guessing**; the one historical near-miss — `--out -dark`
swallowing a mistyped `--dark` as a directory name — was already closed in #76/#82.
That evidence is weak in the direction it points: the transcripts are dominated by
this repo's own development sessions, so they are better proof that the surfaces
are not actively hostile than that they are well named.

## Decision

**No rename ships.** The two defects the review found are documentation defects,
not naming defects, and both are fixed in the same change:

1. **`CONTEXT.md`'s `Stray` entry contradicted the gate.** It read "an element that
   sits outside every frame in a framed diagram. Strays fail the gate." The gate
   says the opposite: elements clear of every frame are explicitly legal (titles,
   legends, captions) and are counted into `stats.outsideAll`, not refused. The
   real `stray` rule is distance-based — more than 1000px from anything else.
   Freezing that entry would have frozen a false statement about the contract.
   The entry now matches the rule; the code keeps its name.

2. **The "public contract" was unpublished.** `CONTEXT.md` calls the problem codes
   "a public contract ... append-only", but no shipped document listed them, so the
   contract was in practice `tools/verify.js`. Freezing an unwritten contract
   freezes every accident in it alongside every decision.
   `skills/excalidraw-diagram/reference/problem-codes.md` now publishes all 26
   codes with their `elements` order and per-code fields, and
   `tests/problem-codes.js` fails when the registry and the sources drift — a new
   rule cannot land without its code being published, and a code marked
   `deprecated` is still listed once it retires, so its name is never reused.

Append-only stands: a code is added, never renamed or repurposed. A code that must
change ships as a new code beside the old one; the old one is marked `deprecated`
in the registry and keeps being emitted while consumers migrate, stops later, and
keeps its row for good. The sync test enforces that reading — a `live` row must be
emitted, and every emitted code must be listed — rather than forbidding the
overlap the migration path depends on.

## Dispositions

Every item on the three surfaces has its own row. All read **keep** — the review
approved no rename — so the column that carries information is the reason.

### CLI flags — 12 items

| CLI | Flag | Disposition |
|---|---|---|
| all three | `<file.excalidraw>` positional | Keep — `check.js` takes many, `render.js` and `revise.js` exactly one; each refuses the other arity. |
| all three | `--` (ends the flags) | Keep — the one escape hatch for a path starting with a dash, and identical across the three, which is what makes the "unknown dash argument is a typo" rule safe. |
| `check.js` | `--json` | Keep — names the format it emits; the only machine-readable face on the gate. |
| `render.js` | `--out DIR` | Keep — a directory, and every other candidate (`--dir`, `--output`) is longer or vaguer. |
| `render.js` | `--scale N` | Keep — raster scale for the frame PNGs, the term the export API itself uses. |
| `render.js` | `--frame N` | Keep — reads as "this frame". It also suppresses the whole-canvas SVG, which is what iterating on one panel wants, and step 5 says so. |
| `render.js` | `--no-frames` | Keep — a near-homograph of `--frame`, but the two together are refused with a "cannot be combined" `UsageError` rather than silently resolved, so the confusable pair cannot do the wrong thing quietly. |
| `render.js` | `--dark` | Keep — names the theme, not the mechanism (a CSS filter), which is the right level for the caller. |
| `render.js` | `--padding N` | Keep — matches Excalidraw's own `exportPadding`. |
| `render.js` | `--background COLOR` | Keep — sets the canvas colour; `--canvas` would name the surface, not the property. |
| `revise.js` | `--no-svg` | Keep — negative form matches `--no-frames`; the positive default (write the SVG) is the one worth having. |
| — | absent: `--help`, `--json` on `render.js`/`revise.js`, `--out` on `revise.js` | Keep the absence — these are additions, not renames, so they stay free after 1.0. `revise.js` rewrites in place deliberately: an output flag would invite a second copy drifting from its source. An unknown flag already prints the usage text and exits 2. |

Exit codes are part of the same contract and are kept as they stand: 2 for a bad
invocation or an unreadable input, 1 for a document the tool refuses, 0 for
success, and the worst code wins across a batch — so a typo'd path outranks a
diagram that failed the rules instead of hiding behind it.

### Problem codes — 26 items

| Code | Disposition |
|---|---|
| `malformed-element` | Keep — names the entry that is not an element at all, and carries the array `index` because there is no id to name. |
| `unknown-type` | Keep — the type is unknown to the gate, which is exactly what it says. |
| `non-finite-geometry` | Keep — `NaN`/`Infinity` is precisely "non-finite"; the noun distinguishes it from `degenerate`. |
| `degenerate` | Keep — a bare adjective beside `non-finite-geometry`'s adjective-plus-noun. Symmetry is worth one word, not two codes carried forever under add-new-plus-deprecate. |
| `duplicate-id` | Keep — unambiguous. |
| `frame-overlap` | Keep — reads in the same subject-first shape as `free-text-overlap`. |
| `missing-container` | Keep — the container is the thing that is gone. |
| `text-overflow` | Keep — collides with a CSS property name, but the meaning is the one that property names. |
| `missing-frame` | Keep — pairs with `missing-container` for the other membership field. |
| `frame-escape` | Keep — "escape" is the verb the skill already uses for content leaving its frame. |
| `unbound-over-frame` | Keep — long, but length is not the cost; ambiguity is, and it has none. |
| `dangling-binding` | Keep — `dangling` is idiomatic for a binding, and the case differs in shape from `missing-*`: a binding object, not a bare id field. |
| `free-text-overlap` | Keep — "free" is the established antonym of bound text here. |
| `arrow-crossing` | Keep — names what the arrow does to a shape it is not bound to. |
| `arrow-buried` | Keep — evocative and unambiguous; the `depth` field quantifies it. |
| `stray` | Keep — the name was right; `CONTEXT.md`'s definition of it was wrong. Fixed above. |
| `unparseable-color` | Keep — the `field`/`value` pair says which colour, so the code needs no qualifier. |
| `text-over-image` | Keep — states the geometry, and the reason (unmeasurable ground) belongs in the message. |
| `low-contrast` | Keep — the standard term. Its `needs` field reads correctly beside `ratio` ("ratio 3.1, needs 4.5"), so `required` buys nothing. |
| `foreign-font` | Keep — "foreign" against the house pair, which is the glossary's framing. |
| `missing-image-bytes` | Keep — names the bytes, not the file entry, which is what is actually absent. |
| `unreadable` | Keep — a bare adjective beside `empty-file`/`invalid-json`/`not-excalidraw`. Same trade as `degenerate`, same answer. |
| `empty-file` | Keep — distinct from `invalid-json` on purpose: an empty file is the common truncation, not a parse failure. |
| `invalid-json` | Keep — unambiguous. |
| `not-excalidraw` | Keep — parses as JSON but is not our document; the negative form is the clearest reading. |
| `check-crashed` | Keep — names a CLI inside a code, but it is `check.js`-only: the in-process gate throws a `GateError` instead of reporting a code. |

Two shape questions, both kept: `stats.outsideAll` is genuinely opaque about
*what* it counts outside of, but a stats-key rename is a shape break for one word
— the registry documents it instead. And problems carry no `severity` field
because the gate has no warning level, so one today would carry a single value;
adding it later is append-only.

## Consequences

- 1.0 can freeze these three surfaces as they stand.
- The problem-code registry is now a gated artifact: `tests/problem-codes.js` runs
  in `test:fast`, so a rule that lands without publishing its code fails CI.
- The declines above are deliberately conservative. Each one trades a naming
  improvement against a permanent duplicate name under the append-only rule, and
  documentation closed every gap that the rename would have.
- Two additions were noted and rejected as out of scope rather than as bad ideas —
  `--json` on `render.js`/`revise.js`, and `--help` on all three. Both remain free
  to add after 1.0.
