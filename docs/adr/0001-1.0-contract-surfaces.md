# ADR-0001 — The 1.0 contract surfaces survive the breaking-change review unrenamed

- **Status**: accepted
- **Date**: 2026-08-08
- **Context**: issue #93, under the 0.5.0 polish wave (#90)

## Context

1.0 freezes three surfaces: the **skill workflow**, the **CLI flags**, and the
**gate's problem codes**. After 1.0 each rename costs a major version, so this is
the last cheap chance to change a name or a shape we would regret. This ADR is the
record of that pass: every flag, every problem code and every workflow step was
reviewed, and each carries a disposition below.

Evidence was the source plus real session transcripts on the maintainer's machine
(roughly six excalidraw working sessions, July–August 2026), read for what agents
actually retry on rather than for what reads badly. The transcripts showed **no
retry episodes and no flag guessing**; the one historical near-miss — `--out -dark`
swallowing a mistyped `--dark` as a directory name — was already closed in #76/#82.
That evidence is weak in the direction it points: the transcripts are dominated by
this repo's own development sessions, so they are better proof that the surfaces
are not actively hostile than that they are well named.

## Decision

**No rename ships.** The two defects the review found are documentation defects,
not naming defects, and both are fixed in the same change:

1. **`CONTEXT.md`'s `Stray` entry contradicted the gate.** It read "an element that
   sits outside every frame in a framed diagram. Strays fail the gate." The gate
   says the opposite: elements clear of every frame are explicitly legal (titles,
   legends, captions) and are counted into `stats.outsideAll`, not refused. The
   real `stray` rule is distance-based — more than 1000px from anything else.
   Freezing that entry would have frozen a false statement about the contract.
   The entry now matches the rule; the code keeps its name.

2. **The "public contract" was unpublished.** `CONTEXT.md` calls the problem codes
   "a public contract ... append-only", but no shipped document listed them, so the
   contract was in practice `tools/verify.js`. Freezing an unwritten contract
   freezes every accident in it alongside every decision.
   `skills/excalidraw-diagram/reference/problem-codes.md` now publishes all 26
   codes with their `elements` order and per-code fields, and
   `tests/problem-codes.js` fails when the registry and the sources drift — a new
   rule cannot land without its code being published, and a code marked
   `deprecated` must actually have stopped being emitted.

Append-only stands: a code is added, never renamed or repurposed. A code that must
change ships as a new code beside the old one, and the old one is marked
`deprecated` in the registry before it stops being emitted.

## Dispositions

### CLI flags — all kept

`check.js`: `--json`, `--`, one or more positional files, exit 0/1/2.
`render.js`: `--out`, `--scale`, `--frame`, `--dark`, `--padding`, `--background`,
`--no-frames`, `--`.
`revise.js`: `--no-svg`, `--`.

| Item | Disposition |
|---|---|
| `--frame N` / `--no-frames` read as near-homographs | Keep — the contradiction is already refused explicitly (`render.js:114`), so the confusable pair cannot silently do the wrong thing. |
| `--frame N` also suppresses the whole-canvas SVG | Keep — documented in step 5, and it is what iterating on one panel wants. |
| `unreadable` exits 2, not 1 | Keep — deliberate: the worst code wins across a batch, so a typo'd path outranks a diagram that failed the rules instead of hiding behind it. |
| `--out` on `render.js` but not `revise.js` | Keep — `revise.js` rewrites in place by design; an output flag would invite a second copy drifting from the source. |
| No `--json` on `render.js`/`revise.js` | Keep — an addition, not a rename; append-only and free after 1.0. Out of scope here. |
| No `--help` | Keep — an unknown flag already prints the usage text and exits 2, so the failure teaches the surface. An addition, free after 1.0. |
| `--scale`, `--padding`, `--background`, `--dark` names | Keep — each names the thing it sets, no collisions. |

### Problem codes — all kept

| Item | Disposition |
|---|---|
| `degenerate` (bare adjective) beside `non-finite-geometry` (adjective + noun) | Keep — symmetry is worth one word, not two codes carried forever under add-new-plus-deprecate. |
| `unreadable` beside `empty-file` / `invalid-json` / `not-excalidraw` | Keep — same trade, same answer. |
| `dangling-binding` beside `missing-container` / `missing-frame` | Keep — `dangling` is idiomatic for a binding, and the arrow case differs in shape: a binding object, not a bare id field. |
| `stray` | Keep — the name was right; the glossary was wrong. Fixed above. |
| `text-overflow` collides with a CSS property name | Keep — the meaning is the same one the CSS property names. |
| `low-contrast`'s `needs` field | Keep — reads correctly beside `ratio` ("ratio 3.1, needs 4.5"). |
| `stats.outsideAll` — outside all *what* | Keep — genuinely opaque, but a shape break for one word. Documented in the registry instead. |
| No `severity` field on problems | Keep — the gate has no warning level, so a severity field today would carry one value. Adding one later is append-only. |
| `check-crashed` names a CLI in a code | Keep — it is `check.js`-only; the in-process gate throws a `GateError` instead. |
| `unbound-over-frame` is long | Keep — length is not the cost; ambiguity is, and it has none. |
| All 21 element-level and 5 file-level codes reviewed individually | Keep — the full list, with fields, is in `skills/excalidraw-diagram/reference/problem-codes.md`. |

### Skill workflow steps — all six kept

| Step | Disposition |
|---|---|
| 1 — name the kind, list the panels | Keep |
| 2 — map each idea to a shape that means it | Keep |
| 3 — build it from measured text | Keep |
| 4 — pass the gate | Keep; the rule catalogue gained a lead-in sentence and a link to the code registry. |
| 5 — look at every frame | Keep |
| 6 — ship the right files | Keep; it was the only step with no "Done when" line — one added. |

## Consequences

- 1.0 can freeze these three surfaces as they stand.
- The problem-code registry is now a gated artifact: `tests/problem-codes.js` runs
  in `test:fast`, so a rule that lands without publishing its code fails CI.
- The declines above are deliberately conservative. Each one trades a naming
  improvement against a permanent duplicate name under the append-only rule, and
  documentation closed every gap that the rename would have.
- Two additions were noted and rejected as out of scope rather than as bad ideas —
  `--json` on `render.js`/`revise.js`, and `--help` on all three. Both remain free
  to add after 1.0.
